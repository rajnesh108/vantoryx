# V4 — MCP Tools

V4 connects the V3 retrieval agent to external tools through the Model Context Protocol. The agent still searches the indexed PDFs first. It calls a configured MCP server when the question asks for a calculation, or when the passages are still not enough after the retry budget.

| Component | Purpose | Example |
|---|---|---|
| MCP client | Connects to the servers in `MCP_SERVERS` | Local stdio process or an HTTP endpoint |
| Tool catalog | Lists each server's tools and their arguments | `calculators/convert-glucose` |
| Tool choice | Asks the chat model whether one tool applies | Convert 5.6 mmol/L, do not guess a missing weight |
| Tool call | Sends the arguments over MCP and reads the text result | `100.9 mg/dL` |
| Grade | Checks the passages and the tool result together | A conversion can satisfy a unit question |
| Answer | Cites the tool result like any other source | `[2]` after the PDF passages |

```text
User question
    ↓
Plan → Route → Retrieve → Grade          V3 hybrid search
    ↓
Calculation, and no tool has been called yet
    ↓
Choose one MCP tool → call it → grade again
    ↓
Passages are sufficient
    ↓
Answer
    ↓
Passages are not sufficient, and a retry remains
    ↓
Rewrite → retrieve → grade
    ↓
Still not sufficient, and a tool call remains
    ↓
Choose one MCP tool → call it → grade again
    ↓
Answer from the passages and any tool result
```

`POST /api/chat` uses this path when `AGENT_ENABLED` and `MCP_ENABLED` are true. The `agent` trace gains a Tool step. A tool result is also a citation, with category `tool`. Set `MCP_ENABLED=false` to keep the V3 path: plan, route, retrieve, grade, and rewrite, with no tool call.

PostgreSQL, pgvector, and the embedding server stay as they are in [v2.md](./v2.md). Restart the backend after changing `MCP_SERVERS`. The PDFs do not need to be uploaded again.

## Bundled calculator server

When `MCP_SERVERS` is unset, the API starts one local stdio server, `backend-server/src/mcp/calculators.ts`. It exposes three read-only tools:

| Tool | Inputs | Result |
|---|---|---|
| `convert-glucose` | `value`, `from`, `to` | mmol/L ↔ mg/dL, using 1 mmol/L = 18.0182 mg/dL |
| `convert-temperature` | `value`, `from`, `to` | Celsius ↔ Fahrenheit |
| `body-mass-index` | `weightKg`, `heightCm` | weight (kg) / height (m)² |

Each result states the arithmetic. None of them diagnose, stage, or recommend treatment. The answer model is told to cite a tool result as a calculation.

The server speaks MCP on stdout. The API spawns it with Node and keeps the process for later calls. `GET /api/health` reports the configured server names. It does not open a connection.

## Other servers

`MCP_SERVERS` is a JSON array of at most 8 servers. The chat request cannot add a server, a command, or a URL.

```json
[
  {
    "name": "calculators",
    "transport": "stdio",
    "command": "node",
    "args": ["--import", "tsx", "src/mcp/calculators.ts"]
  },
  {
    "name": "guidelines",
    "transport": "http",
    "url": "http://127.0.0.1:3000/mcp",
    "headers": { "Authorization": "Bearer local" }
  }
]
```

Stdio `command` and `args` are spawned directly, not through a shell. An HTTP URL must be `http` or `https`, without a username or password in the URL. Put a credential in `headers`. Only point this setting at servers you trust: a tool result is given to the answer model as a source.

If one server fails to connect, the others stay available. If every server fails, the search result is kept and the trace says MCP is not connected. The API retries the connection after 30 seconds.

## When a tool runs

A calculation question is one that includes a number and one of: mmol or mg/dL, Celsius or Fahrenheit, BMI, or both a kilogram weight and a centimeter height. After the first grade, the agent asks the model to pick at most one tool. A dose such as "metformin 500 mg" is not treated as a calculation, so the V3 rewrite still runs first.

For every other question, a tool is considered only after the grade fails and `AGENT_MAX_RETRIES` is spent. The model must use numbers that appear in the question. If it names a tool that is not connected, or no tool applies, the passages already retrieved are kept.

`MCP_MAX_CALLS` is the number of tool calls in one request. The default is 1. `0` turns calls off.

A successful tool result is appended after the PDF passages and graded with them. The answer can cite both. A tool error is not cited.

## Configuration

| Setting | Default | Role |
|---|---|---|
| `MCP_ENABLED` | `true` | Connect the configured MCP servers |
| `MCP_MAX_CALLS` | `1` | Tool calls for one question. Allowed range 0–2 |
| `MCP_TIMEOUT_MS` | `20000` | Limit for connect, list, and call |
| `MCP_SERVERS` | bundled calculators | JSON array of stdio and HTTP servers |

`AGENT_ENABLED=false` skips the graph, so no tool runs. The V3 knobs still apply to search: `AGENT_MAX_QUERIES`, `AGENT_MAX_RETRIES`, `TOP_K`, and the reranker settings.

In code the client is `openMcpSession` in `backend-server/src/services/mcp/session.ts`. The graph node is `tools` in `backend-server/src/services/agent/graph.ts`.

## Limits

- The bundled server converts units and computes BMI. It does not browse the web or read a record system.
- A tool can only return what that server implements. A missing indexed fact is still missing if no tool computes it.
- The model chooses the arguments. The server rejects values outside the tool's range, and that rejection is not used as a citation.
- One weak local model can skip a relevant tool or call one the question did not need. `MCP_MAX_CALLS` caps that.
- Changing servers requires a backend restart. The tool list is read when the connection opens.
