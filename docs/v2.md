# V2 — Hybrid Retrieval + Reranking for RAG

Your V2 architecture improves your existing Basic RAG by combining BM25 keyword search + vector similarity search + a reranker to retrieve more relevant document chunks.

| Component | Purpose | Example |
|---|---|---|
| BM25 | Finds exact keywords and terms | diabetes medication |
| Vector Search | Finds semantically similar content | How is high blood sugar treated? |
| Hybrid Fusion | Combines keyword and vector results | Reciprocal Rank Fusion (RRF) |
| Reranker | Reorders candidates by query relevance | Cross-encoder reranker |
| LLM | Generates an answer using top-ranked chunks | GPT or a local LLM |

```text
User Query
    ↓
BM25 Search                 Vector Search
Keyword matching            Semantic matching
    ↓
Fusion — RRF
Merge and deduplicate candidates
    ↓
Reranker
Score query–chunk relevance
    ↓
Top-K Context
    ↓
LLM → Grounded Answer
```

PostgreSQL with pgvector:

- Vector database: PostgreSQL + pgvector
- Keyword retrieval: PostgreSQL full-text search with `tsvector` and `tsquery`
- Fusion: Reciprocal Rank Fusion (RRF)
- Reranker: BGE Reranker or a suitable cross-encoder
- Configuration: Keep retrieval settings configurable through environment variables.

In code:

| Setting | Value | Role |
|---|---|---|
| `TOP_K` | `5` | Final chunk result |
| `BM25_TOP_K` | `20` | Keyword specific chunk |
| `VECTOR_TOP_K` | `20` | Semantic matching chunk |
| `RERANK_TOP_K` | `5` | Rerank more relevant chunk |
| `RERANKER_ENABLED` | `True` | |

`POST /api/chat` reads those variables. Keyword search ranks each chunk’s `content_tsv` with PostgreSQL `ts_rank_cd` and `websearch_to_tsquery`. Reciprocal rank fusion merges that list with the vector list. When `RERANKER_ENABLED` is true, the embedding server scores the fused chunks with `RERANKER_MODEL` (`BAAI/bge-reranker-base` by default) and keeps `RERANK_TOP_K`. If the reranker cannot be reached, the fused order is kept and cut to `TOP_K`.

Restart the backend so it adds `content_tsv` to existing chunks. Restart the embedding server so it loads the reranker. Stored chunk text is indexed by that column, so the PDFs do not need to be uploaded again.

## How BM25 works

BM25 is a ranking algorithm that estimates how relevant a document is to a search query. Its score mainly depends on three factors:

1. Term frequency (TF): How often a query term appears in a document, with diminishing returns.
2. Inverse document frequency (IDF): How rare or informative the term is across the document collection.
3. Document length: Adjusts for document length so longer documents do not automatically dominate.

For example, a rare drug name may be more informative than a common word such as “patient”.

BM25 does not understand meaning like an embedding model. It scores textual matches.

BM25 searches the original text of your document chunks, not the vector embeddings you saved during the embedding process.

Example:

```text
Metformin 500 mg is prescribed to help manage Type 2 Diabetes.
```

After chunking and embedding, your database might store something like this:

| id | chunk_text | embedding |
|---|---|---|
| 1 | Metformin 500 mg is prescribed to help manage Type 2 Diabetes. | `[0.12, -0.34, 0.87, ...]` |
| 2 | Insulin helps regulate blood glucose levels. | `[0.21, 0.45, -0.16, ...]` |

The embedding column contains numerical vectors representing the text's semantic meaning. The `chunk_text` column contains the actual text.

## Why combine BM25 with vector search?

| User query | BM25 strength | Vector search strength |
|---|---|---|
| ICD-10 E11.9 | Exact code matching | May recognize related diabetes concepts |
| Metformin 500 mg | Exact medication and dosage terms | Related medication information |
| How can blood sugar be controlled? | Matches overlapping words | Finds semantically related passages |
| CKD stage 3b | Matches specific terminology | Can retrieve passages discussing moderate-to-severe kidney disease |

Neither method guarantees the correct clinical result. For healthcare RAG, exact identifiers, dosages, negations, and clinical context need particular care.
