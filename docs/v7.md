# V7 — Local LLM

V7 chooses which chat provider answers questions. Planning, grading, tools, evaluation, and the request trace all go through one provider interface. The Express API does not load model weights itself.

```text
Vantoryx RAG application
Node.js and Express
    ↓
LLM provider interface
    ↓
Cloud                         Local
OpenAI                        llama.cpp
                                  ↓
                              Local GGUF model
```

| Provider | Family | Setting | Default address | What you run |
|---|---|---|---|---|
| Ollama | local | `ollama` | `http://127.0.0.1:11434/v1` | `ollama serve`, then a pulled model |
| llama.cpp | local | `llamacpp` | `http://127.0.0.1:8081/v1` | `llama-server` with a GGUF file. Port 8080 is pgAdmin |
| OpenAI | cloud | `openai` | `https://api.openai.com/v1` | An API key |

Local servers and OpenAI share `POST /v1/chat/completions`. A GGUF file is an argument to `llama-server`. Set `LLM_GGUF` to that path so the API can default `LLM_MODEL` to the file name, such as `guide.gguf`.

```text
LLM_PROVIDER
    ↓
Cloud: OpenAI
Local: llama.cpp or Ollama
    ↓
Health checks a local or OpenAI model list
    ↓
completeChat
Plan, grade, tool choice, and the answer
```

PostgreSQL, pgvector, and the embedding server stay as they are. Changing the chat provider does not re-index PDFs. Restart the API after changing `LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_GGUF`, or `OPENAI_API_KEY`.

## Health

`GET /api/health` probes the chat server for up to 3 seconds. The `llm` object includes:

| Field | Meaning |
|---|---|
| `provider` | `ollama`, `llamacpp`, or `openai` |
| `family` | `local` or `cloud` |
| `label` | Ollama, llama.cpp, or OpenAI |
| `status` | `ok`, `unavailable`, or `model-missing` |
| `models` | Up to 20 names the server listed |
| `model` | The name sent on chat requests |
| `gguf` | The `LLM_GGUF` path, or null |
| `baseUrl` | The address those requests use |

`ok` means the server answered and `LLM_MODEL` is in the list. Ollama tags such as `llama3.1:latest` match `LLM_MODEL=llama3.1`. `unavailable` means the probe could not read a model list. `model-missing` means the server is up and the configured name is absent. The search page shows those two states. Search still returns passages when the chat model is down.

Ollama is checked at `/v1/models` first. If that list is empty or the path fails, health reads `http://<host>/api/tags`. llama.cpp and OpenAI are checked at `/v1/models`.

## Configuration

| Setting | Default | Role |
|---|---|---|
| `LLM_PROVIDER` | `ollama` | `ollama`, `llamacpp`, or `openai` |
| `LLM_BASE_URL` | The provider default | Override the address. Must be `http` or `https` |
| `LLM_MODEL` | Depends on the provider | Model name sent on each request. A GGUF file name is the llama.cpp default when `LLM_GGUF` is set |
| `LLM_GGUF` | empty | Path of the GGUF file passed to `llama-server`. The API records it and does not open the file |
| `LLM_API_KEY` | empty | Ollama accepts a placeholder such as `ollama`. llama.cpp usually needs none. OpenAI in the model menu uses `OPENAI_API_KEY` |
| `LLM_TIMEOUT_MS` | `120000` | Limit for a chat completion. The health probe stays at 3 seconds |

Leave `LLM_BASE_URL` unset when you only want to switch local servers. A set URL wins over the provider default, so an old Ollama URL stays in use until you clear it.

The search page lists the models each provider can run. A question uses the model selected there. Planning, grading, and the answer stay on that choice. Evaluation keeps using the server default in `.env`. OpenAI appears when `OPENAI_API_KEY` is set. A provider whose server is down stays in the list and cannot be selected.

In code the choice is `parseProvider` and `resolveLlmBaseUrl` in `backend-server/src/services/localLlm.ts`. `completeChat` in `backend-server/src/services/llm.ts` calls `completeOpenAiChat` in `backend-server/src/services/chatProvider.ts`. The search selection is `withChatTarget` in `backend-server/src/services/llmChoice.ts`.

## Starting a server

Ollama:

```powershell
ollama serve
ollama pull llama3.1
```

llama.cpp, from a build that includes `llama-server`:

```powershell
llama-server -m C:\models\guide.gguf --port 8081
```

Set `LLM_PROVIDER=llamacpp`, `LLM_GGUF` to that file, and `LLM_MODEL` to the id `GET /v1/models` returns. When `LLM_MODEL` is empty, the API uses the GGUF file name.

OpenAI: set `OPENAI_API_KEY`, then choose an OpenAI model on the search page. Setting `LLM_PROVIDER=openai` makes OpenAI the server default.

## Limits

- Vantoryx does not download weights, compile llama.cpp, quantize a model, or start `llama-server`.
- One provider is active per API process. Switching means an edit and a restart.
- The GGUF path is an argument to `llama-server`. `LLM_GGUF` records that path for the API.
